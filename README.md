# BatteryManager for macOS

Менеджер батареи для MacBook: мониторинг состояния, история и графики,
защита от перегрева, иконка Dock с процентом заряда.

## Возможности

- 🔋 Процент заряда в строке меню и на иконке в Dock (цвет по состоянию)
- 📊 Визуализация: заряд, температура, мощность адаптера и системы
- 📈 История за 24 часа на SQLite + три графика (Swift Charts)
- 🔥 Защита от перегрева: предупреждение 35-40°C, отключение заряда выше 40°C
- 💚 Здоровье батареи: ёмкости, износ, циклы, состояние
- 🎚️ Лимит заряда 80–100% средствами macOS, режимы «Заряд» и «Разряд»
- 🎨 Liquid Glass дизайн (полупрозрачные поверхности, градиенты, тени)

## Системные требования

- macOS 13 Ventura или новее
- Apple Silicon или Intel процессор

## Технологии

- Swift + SwiftUI, Swift Charts
- IOKit (реестр `AppleSmartBattery` / `AppleSmartBatteryPack`) — данные батареи
- SQLite3 (системный) — история за 24 часа
- AppKit (Dock tile, `NSPanel`) — иконка Dock и панель приложения
- SMC через IOKit — управление зарядкой (свой C-слой: AppleSMC требует
  точной раскладки структуры, которую Swift не гарантирует)

## Использование

```bash
scripts/build-app.sh          # собрать build/BatteryManager.app
scripts/build-app.sh --run     # собрать и запустить
```

После запуска:

- в **строке меню** появляется процент заряда — клик открывает окно
  с вкладками «Статус», «Графики», «Здоровье», «Настройки»;
- на **иконке в Dock** виден процент заряда и цвет состояния
  (зелёный — зарядка, белый — разрядка, янтарный ⚠️ — нагрев,
  красный 🔥 — критический перегрев); клик по иконке открывает панель;
- история пишется в
  `~/Library/Application Support/BatteryManager/history.db` раз в минуту.

## Разработка и тесты

Сборка идёт без Xcode, через Command Line Tools: архитектура и SDK
берутся с машины сборки, минимальная система приложения — macOS 13.
Песочница запрещает запись module cache компилятора в `/var/folders`,
из-за чего `swift test` не может скомпилировать манифест пакета. Поэтому тесты
запускаются напрямую через `swiftc` с module cache внутри репозитория:

```bash
scripts/run-tests.sh
```

Тесты написаны на Swift Testing (`import Testing`). При установке
полноценного Xcode тот же набор заработает и через `swift test`.

## Ограничение заряда

На macOS 26 и новее лимит заряда держит сама система (тот же механизм,
что в «Настройках → Аккумулятор»). Приложение только задаёт значение:

- лимит действует во сне и при закрытом приложении;
- права администратора и helper для него не нужны;
- допустимые значения задаёт система: на macOS 27 это 80, 85, 90, 95 и
  100% (100% — лимит выключен). Ниже 80% система не принимает;
- на лимите Mac питается от адаптера, батарея не заряжается и не
  разряжается; если заряд выше лимита, система сама снижает его до лимита;
- лимит, изменённый в Настройках macOS, приложение подхватывает за 30 секунд.

Кнопки на вкладке «Статус»:

- **80% … Выкл** — лимит заряда;
- **«Заряд»** — зарядить до 100% один раз; на 100% лимит возвращается сам.
  Полезно раз в несколько недель, чтобы процент заряда показывался точно;
- **«Разряд»** — отключить питание от адаптера, пока режим не отменён
  (нужен helper).

Успех показывается только после подтверждения системой или helper; отказ —
с текстом ошибки и кнопкой «Повторить».

### Helper

Нужен для двух вещей: режима «Разряд» и остановки зарядки при перегреве
(>40°C). Запись в SMC требует прав root, поэтому helper
(`Sources/Helper/helper.c`) ставится один раз и принимает только команды
`hold`, `allow`, `status`. Установка (macOS спросит пароль администратора):

```bash
open Установка-Helper.command
```

Перед сном и при выходе из приложения удержание helper снимается: команда
живёт в SMC сама по себе, и без приложения её некому отменить. После
аварийного завершения оно снимается при следующем запуске.

### Проверено на Mac16,12, macOS 27

- лимит через систему: 85% и 80% приняты, 70% отклонён; при лимите 100%
  зарядка возобновилась (28 Вт от адаптера);
- helper: `hold` — питание от адаптера упало с 28 до 0,4 Вт, Mac перешёл
  на батарею; `allow` — зарядка вернулась. Управляющий ключ — `CHIE`
  (`08` — адаптер отключён, `00` — включён);
- ключей `CHTE`, `CH0B`/`CH0C` в SMC нет; `CHSC` и `CHLT` только для чтения
  (`CHLT` показывает действующий лимит).

Лимит системы ставится через закрытый системный фреймворк PowerUI —
публичного API у него нет, и в следующих версиях macOS он может измениться.
Если его нет, приложение держит лимит само через helper (значения 20–100%,
работает только пока приложение запущено) — эта схема покрыта тестами,
но на реальной машине не проверялась.

AlDente использует тот же лимит системы: если он запущен, значения будут
перебивать друг друга.

Что осталось:

- английская локализация, VoiceOver и Reduce Motion;
- подпись Developer ID и нотаризация (нужны только для раздачи другим людям).
